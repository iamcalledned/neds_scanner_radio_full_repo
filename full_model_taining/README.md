# Scanner-radio Whisper Medium training

This flow fine-tunes the English Whisper Medium checkpoint on the manually
corrected scanner exports. It uses `edited_transcript` as ground truth and only
falls back to the decoded `transcript` when no manual edit exists.

## Configuration and target directories

Edit `training_config.json` before running the flow. Relative paths are resolved
relative to the config file, not the current shell directory:

```json
{
  "exports_dir": "exports",
  "manifests_dir": "manifests",
  "output_dir": "outputs/whisper-medium-scanner",
  "ctranslate2_output_dir": "outputs/whisper-medium-scanner-ct2"
}
```

`exports_dir` must contain `train`, `eval`, and `test` subdirectories. Absolute
paths are supported. The same config also contains model and training
hyperparameters. Command-line options override config values for a single run.
Use a different config with:

```bash
./run_training.sh --config /absolute/path/to/training_config.json
```

or set `TRAINING_CONFIG` when using the wrapper:

```bash
TRAINING_CONFIG=/absolute/path/to/training_config.json ./run_training.sh
```

`exclude_filenames` may list WAV or JSON basenames that must not enter a run.
Every configured exclusion is recorded in the split's rejection report.
`alignment_model` may select a separate timestamp-capable checkpoint for
splitting long audio; it does not change the model initialized for training.

## 1. Create the environment

Whisper Medium has 769M parameters. A CUDA GPU is strongly recommended. Install
a CUDA-enabled PyTorch build using the command generated by the
[official PyTorch installer](https://pytorch.org/get-started/locally/), then
install the remaining packages:

On this machine, the existing `whisper52` shell helper activates
`/home/ned/venv_whisper52`. The `run_training.sh` wrapper automatically
activates that environment, so it is not necessary to run `whisper52` first.
Verify or update that environment with:

```bash
cd /home/ned/Documents/neds_scanner_radio_full_pipeline_with_git/full_model_taining
whisper52
python -c "import torch; print(torch.cuda.get_device_name(), torch.cuda.is_available())"
pip install -r requirements-training.txt
```

To select a different environment:

```bash
WHISPER_VENV=/absolute/path/to/venv ./run_training.sh
```

Do not start a Medium training run until the last command reports a GPU and
`True`. The base model download is roughly 3 GB and is performed automatically
by Transformers on the first run.

## 2. Validate and prepare manifests

```bash
.venv/bin/python prepare_data.py
```

This writes `manifests/{train,eval,test}.jsonl`, a summary, explicit rejection
reports, and queues long recordings in `*_long.jsonl`.

Review `manifests/summary.json` before training. To require manual text for
every sample, add `--no-allow-transcript-fallback`.

## 3. Align long recordings

```bash
.venv/bin/python align_long_audio.py
```

The alignment stage runs the configured base Whisper model with word
timestamps, aligns the recognized words to `edited_transcript`, and adds
segments of at most 29 seconds to each final manifest. Segment rows reference
start/end offsets in the original WAV, so audio is not duplicated. Review
`manifests/alignment_report.json`. Alignments below the configured confidence
threshold are retained using interpolated word timing and flagged with
`low_confidence: true`.

Completed alignments are cached under `manifests/alignment_cache`, so an
interrupted run resumes without repeating completed recordings. To deliberately
discard that cache:

```bash
python align_long_audio.py --rebuild-alignment-cache
```

## 4. Train and score the held-out test set

```bash
.venv/bin/python train_whisper.py
```

Conservative defaults use batch size 1, 16-step gradient accumulation, FP16,
gradient checkpointing, five epochs, validation every 100 updates, and retain
the best checkpoint by word error rate (WER). The final model is stored under
`outputs/whisper-medium-scanner/best`; metrics are stored alongside it.

Common adjustments:

```bash
# Less VRAM use (also prevents encoder updates):
.venv/bin/python train_whisper.py --freeze-encoder

# Resume an interrupted run:
.venv/bin/python train_whisper.py \
  --resume-from-checkpoint outputs/whisper-medium-scanner/checkpoint-300

# Train the multilingual Medium checkpoint instead:
.venv/bin/python train_whisper.py --model openai/whisper-medium

# For an Ampere-or-newer GPU with working BF16:
.venv/bin/python train_whisper.py --bf16 --no-fp16
```

`run_training.sh` is a convenience wrapper that prepares manifests, aligns long
recordings, and starts training, but dependencies still need to be installed
first:

```bash
./run_training.sh
```

## 5. Convert for the existing faster-whisper scanner

The training output is a Hugging Face model. If the live scanner uses
faster-whisper/CTranslate2, install the converter and convert the best model:

```bash
.venv/bin/pip install "ctranslate2>=4.5"
.venv/bin/python convert_to_ctranslate2.py
```

The converter reads both its source and destination from `training_config.json`.
Point the scanner at the configured CTranslate2 directory only after comparing
its WER and spot-checking transcripts against the held-out test set.

## Dataset policy

- `train` updates model weights.
- `eval` selects the best checkpoint and tunes training decisions.
- `test` is scored once after training and must not be moved into `train`.
- Empty, missing, malformed, non-mono, and non-16 kHz samples are rejected.
- Recordings over 30 seconds are word-aligned to their manual transcript and
  represented as offset-based training segments; they are never truncated with
  an unsplit full-recording label.
- The export folders are read-only inputs; generated files go to `manifests`
  and `outputs`.
